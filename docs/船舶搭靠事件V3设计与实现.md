# 船舶搭靠事件 V3：保险风险行为识别设计与实现

## 1. 结论

V3 将搭靠从“近距离低速轨迹候选”升级为：

> 两艘商船在开放海域以 1～3 节低速同向并行，在 500 米内保持至少 30 分钟的异常伴随关系。

事件结论不再只由距离阈值决定，而由四组证据共同形成：

1. 对象：商船 + 商船，优先油轮、散货船、集装箱船；
2. 行为：近距离、距离稳定、速度接近、同向并行、持续伴随；
3. 场景：港口排队排除、锚地等待降权、开放海域升权；
4. 质量：AIS 时间差、覆盖率、缺口和点数决定置信度及风险上限。

## 2. 改造前完整链路

```text
AIS
  HBase 主船历史轨迹 / getRecentAis 区域回放
    ↓
船舶 A 轨迹
  TrajectoryLoaderService 转为 TrajectoryPoint
  清洗非法经纬度、时间、速度，按时间排序和去重
    ↓
候选船搜索
  主船先提取低速窗口
  以窗口轨迹 bbox + 0.5nm 缓冲查询 getRecentAis
  返回轨迹按 targetMmsi 分组
  点数、低速点、时间差、距离、持续时间预过滤
    ↓
两船轨迹匹配
  遍历主船点
  在最大时间差内选“时间最近、距离次近”的目标船点
    ↓
距离计算
  TrajectoryUtils.distanceNm 计算球面海里距离
  V2 正式确认默认小于 0.15nm
    ↓
速度和航向判断
  双方速度不超过 2kn
  SOG 差不超过 1kn
  COG 差不超过 30°
  原实现将 180° 反向也视为平行
    ↓
搭靠事件
  连续匹配点形成片段
  弱候选 20min/3 点，正式候选 30min/6 点
  同船对近时空片段合并
  写 ship_behavior_event 和 ship_behavior_event_detail
    ↓
风险评分
  距离、持续时间、点数、时间差、速度差、航向、AIS gap
  仅用 AIS navStatus 对锚泊/系泊降权
  无外部场景时限制自动风险等级
```

对应代码入口：

- 调度：`ShipBehaviorJob`
- 编排：`ShipBehaviorAnalysisService.analysisAlongside/analysisAlongsideBatch`
- 主船轨迹：`TrajectoryLoaderService`
- 区域回放：`SpatialAisReplayClient`、`ReplayAisPointParser`
- 候选召回：`ShipAlongsideReplayCandidateProvider`
- 双船检测：`ShipAlongsideDetector`
- 事件落库：`ShipBehaviorEventRepository`、`ShipBehaviorEventDetailRepository`
- 表结构：`ship_behavior_event.sql`、`ship_behavior_event_detail.sql`

### 2.1 改造前的关键不足

- 商船过滤主要作用于批量主船列表，回放目标船没有船型过滤；
- 候选搜索半径不是需求要求的 10 海里；
- 没有最低速度，静止锚泊容易进入候选；
- 反向 180° 会遇被视为“平行”；
- 没有 `distance_variance`、平均航向差等稳定伴随特征；
- 港口、锚地、开放海域没有进入事件判定；
- 距离近可以形成事件，尚不能表达“海上异常伴随”；
- 每日扫描量、候选组合量和风险分布没有统一输出入口。

## 3. V3 识别规则

### 3.1 对象范围

船型来自 `ais41.recentships.type`。

优先商船：

- 油轮、油船、Tanker；
- 散货船、Bulk Carrier；
- 集装箱船、Container Ship；
- 其他明确货运商船，如 Cargo、LNG/LPG、化学品船、滚装船。

明确降噪：

- 渔船、游艇、小艇；
- 拖轮、拖带船；
- 工程/服务/近海作业船；
- 客船、引航船。

船型缺失时不直接当成渔船排除，保留为“画像未知”，但不获得商船组合加分。

### 3.2 两级空间过滤

第一级为召回，不做全量船对：

- 只对已经进入低速窗口的主船查询；
- 以主船窗口轨迹 bbox 向外扩 10 海里；
- 由空间 AIS 接口返回该局部窗口内船舶；
- 明确非商船在精确轨迹匹配前过滤。

第二级为事件确认：

- 两船匹配距离不超过 `0.27nm`，约 500 米；
- 最大 AIS 时间差 10 分钟；
- 至少 3 个预过滤匹配点且覆盖 20 分钟；
- 正式事件至少 6 点且覆盖 30 分钟。

### 3.3 行为确认

正式确认点同时满足：

- 双方 SOG 均在 1～3kn；
- `abs(speedA - speedB) <= 1kn`；
- 同向圆周 COG 差不超过 30°；
- 不再把 180° 反向航行视为平行；
- 事件 `parallel_ratio >= 0.8`；
- 持续至少 30 分钟。

COG 缺失时不会伪造航向证据；事件可以保留为低置信候选，但不能因缺失数据获得同向并行分。

### 3.4 正常场景

| 场景 | 判定 | 处理 |
|---|---|---|
| 港口排队 | `near_port=true` 且附近船数不少于 5 | `EXCLUDED_NORMAL`，原因 `PORT_QUEUE_LIKELY`，评分乘 0.15 |
| 港口作业 | `near_port=true` | 降权，评分乘 0.35 |
| 锚地等待 | `near_anchor=true` | 降权，评分乘 0.40 |
| AIS 锚泊/系泊状态 | 任一船状态为 anchored/moored/berth | 降权，评分乘 0.50 |
| 开放海域异常伴随 | 非港口、非锚地，商船同向持续伴随 | 增加开放海域场景分 |
| 场景维表不可用 | 无法确认港口、锚地或开放海域 | 不升场景风险，保留等级封顶 |

港口数据来自 `dataanalysis.zones_with_port_id`。锚地数据来自 `ais41.alertzones` 中名称包含 `anchor`、`锚地` 或 `锚泊` 的区域。

## 4. Alongside Feature

V3 将以下特征写入事件表，并同时保留在 `score_detail_json`：

| 分类 | 字段 | 说明 |
|---|---|---|
| 距离 | `min_distance_nm` | 最小距离 |
| 距离 | `avg_distance_nm` | 平均距离 |
| 距离 | `distance_variance_nm2` | 距离方差，衡量伴随稳定性 |
| 运动 | `course_difference_degree` | 平均同向航向差 |
| 运动 | `speed_difference_knots` | 平均 SOG 差 |
| 运动 | `parallel_ratio` | 满足同向阈值的有效点比例 |
| 环境 | `near_port` | 港口场景 |
| 环境 | `near_anchor` | 锚地场景 |
| 环境 | `open_sea` | 开放海域 |
| 对象 | `own_ship_type` | 主船类型 |
| 对象 | `target_ship_type` | 目标船类型 |
| 时间 | `duration_minutes` | 伴随持续时间 |
| 质量 | `track_coverage_ratio` | AIS 轨迹覆盖率 |
| 质量 | `ais_gap_count` | 事件内 AIS 缺口数 |

## 5. AlongsideRiskScore

单事件原始分为：

```text
rawScore =
  baseEvidenceScore       0..55
  + sceneRiskScore        0 或 20
  + counterpartyRiskScore 0 或 10
  + behaviorRiskScore     0 或 5
  + durationRiskScore     0..15
```

### 5.1 基础行为证据

- 极近距离：7～10 分；
- 距离方差稳定：4～10 分；
- 速度差：5～8 分；
- 平均同向航向差合格：8 分；
- `parallel_ratio` 合格：8 分；
- AIS 时间和覆盖质量：3～6 分；
- 正式点数：5 分。

### 5.2 风险增强

- 开放海域：20 分；
- 已确认商船 + 商船：10 分；
- 事件内 AIS gap：5 分；
- 30/60/120/360 分钟持续时间：5/8/12/15 分。

### 5.3 风险抑制

- 正常场景按第 3.4 节乘系数；
- LOW 置信度再乘 0.6；
- 弱候选最高 20 分且固定 L1；
- 无场景数据、无对象风险数据且无其他外部证据时，自动等级最高 L2；
- 默认自动输出最高 L3，L4 需要显式启用和更强外部证据。

风险等级：

| 分数 | 等级 |
|---|---|
| 0 | L0 |
| 0～25 | L1 |
| 25～50 | L2 |
| 50～75 | L3 |
| 75～100 | L4 |

## 6. Alongside Analyzer Service

### 6.1 当前仓库可运行链路

```text
XXL Job
  ↓
商船主船列表
  ↓
HBase 主船轨迹
  ↓
低速窗口
  ↓
10nm bbox 空间召回
  ↓
目标船型过滤
  ↓
500m 精确轨迹匹配
  ↓
行为特征 + 场景识别
  ↓
AlongsideRiskScore
  ↓
事件/轨迹明细/批次状态入库
```

`PAIR`、`AUTO`、`BATCH AUTO` 三种入口均保留。事件和轨迹接口继续返回 `ShipBehaviorTrace`，与 Loitering 的接口形态一致。

### 6.2 实时化部署方案

本仓库当前 AIS 来源是 HBase 历史轨迹与 HTTP 区域回放，不包含消息队列消费者。因此实时化应在不改变检测器接口的前提下增加输入适配层：

1. AIS 消费者按 MMSI 更新最近 60～90 分钟轨迹状态；
2. 船型画像过滤后，只将商船写入位置索引；
3. 使用 geohash/H3 或等距网格维护当前船位，查询本格及邻格，最大召回半径 10nm；
4. 候选对使用规范键 `min(mmsiA,mmsiB)|max(mmsiA,mmsiB)` 去重；
5. 仅对局部候选对追加匹配点，不进行全部船舶笛卡尔积；
6. 候选状态达到 30 分钟后调用与批处理相同的 V3 特征、场景和评分逻辑；
7. 超过断点阈值时关闭事件并入库；
8. 通过事件键和版本实现幂等写入。

建议状态 TTL 为 90 分钟；空间索引使用最新点，事件状态保存匹配轨迹，不把全量历史 AIS 放入内存。

## 7. 数据库设计

V3 复用 `ship_behavior_event`，新增第 4 节的 10 个一等字段。`ShipBehaviorTableInitializer` 会对已有表逐列迁移。

保留：

- `ship_behavior_event`：事件摘要、特征、评分和场景；
- `ship_behavior_event_detail`：OWN/TARGET 事件轨迹快照；
- `ship_behavior_alongside_batch_status`：窗口运行状态和候选统计。

没有将特征只塞入 JSON：关键特征可直接用于统计、核保规则、样本筛选和模型训练；JSON 继续保存完整评分解释。

## 8. 每日统计

新增调度入口：

```text
shipAlongsideDailyStatsJobHandler
```

参数示例：

```json
{
  "batchNo": "alongside-20260727",
  "startTime": "2026-07-27 00:00:00",
  "endTime": "2026-07-28 00:00:00"
}
```

输出：

- `scannedMerchantShips`：批次完成窗口中的主船去重数；
- `candidatePairs`：各扫描窗口候选目标组合数之和；
- `confirmedEvents`：排除弱候选和正常港口场景后的正式事件数；
- `L1/L2/L3/L4`：已落库事件风险等级分布。

`candidatePairs` 是“主船扫描窗口维度”的候选组合工作量指标，同一船对跨窗口出现时会分别计数。

## 9. 测试案例

### 9.1 高风险

- 油轮 + 散货船；
- 开放海域；
- 距离小于 500 米且方差低；
- 双方 1～3kn；
- 同向航向差小于 30°；
- 60 分钟持续伴随；
- 预期：正式事件、`VALID_RISK_EVENT`、分数大于 50。

### 9.2 低风险/正常

- 港口内 8 船聚集排队；
- 预期：`EXCLUDED_NORMAL/PORT_QUEUE_LIKELY`。

- 锚地区域低速伴随；
- 预期：`DOWNGRADED_NORMAL_LIKELY/ANCHORAGE_WAITING_LIKELY`。

- AIS 状态锚泊或系泊；
- 预期：降权，不作为开放海域高风险。

### 9.3 误报控制

- 180° 反向会遇：不成事件；
- 双方低于 1kn 静止：不成 V3 事件；
- 一方为渔船或拖轮：不进入商船搭靠事件；
- 时间差超过 10 分钟：不匹配；
- 仅短暂靠近：不成正式事件；
- 场景维表缺失：不自动升为高风险。

## 10. 与 Loitering 的接口统一

- 检测器仍提供 `detectWithTrace` 并返回 `List<ShipBehaviorTrace>`；
- 事件统一使用 `ShipBehaviorEvent`；
- 轨迹快照统一使用 `ShipBehaviorEventDetail`；
- 都有 `rule_version`、`event_sub_type`、`severity_level`、`event_score`、
  `confidence_level`、`exclusion_flag`、AIS 质量和评分 JSON；
- 都由 `ShipBehaviorAnalysisService` 编排，并提供单船、批量、进度和日志；
- V3 新增的 `AlongsideContext` 只承载双船画像和场景，不改变 Loitering 的单船检测语义。

## 11. 已知运行边界

- “附近船数”当前来自区域回放结果船数，是港口拥挤度的可解释代理；实时服务应改为 10nm 空间索引内的同时在线商船数；
- 现有港口/锚地多边形只判断事件中心是否落区，若业务要求“距边界若干海里”，需在维表预处理或空间服务中增加缓冲；
- 船型缺失时采用未知画像而不是强排除，避免画像缺失造成系统性漏报；
- 港口报备 STS、制裁对象、货种、船东关联和历史复发尚未接入，预留在场景/对象/复发评分项，不应在缺少证据时输出自动 L4。
